# PROCESS STUDIO 앱

https://processstudio.netlify.app — 코치·선수용 축구 PWA (정적 HTML/JS, 빌드 없음).

## 배포
- `main` 에 머지되면 Netlify 가 자동으로 배포한다 (GitHub ↔ Netlify 연결, `netlify.toml`).
- 작업은 브랜치에서 모아 PR 로 올리고, 확인 후 한 번에 머지한다. PR 마다 deploy preview 주소가 생긴다.
- 판 번호: `sw.js` 의 `CACHE='process-X.XXX'` 와 `studio/app.html` 의 `window.PS_BUILD` 를 같이 올린다.

## 키
- Supabase **publishable** 키는 `studio/app.html` 의 `window.PS_SYNC` 에 있다. RLS 전제의 브라우저 공개용 키라 저장소에 있어도 된다.
- secret(service_role) 키는 서버 전용 — 이 저장소·Netlify·GitHub 어디에도 넣지 않는다.

설계 문서·SQL·과거 기록은 `scua5673/process-studio` 에 있다.

## 저장 회귀 검증

Node.js 22 이상에서 별도 패키지 설치 없이 실행한다.

```bash
node --test tests/*.test.cjs
```

테스트는 현재 파일의 실제 함수를 읽어 가상 저장소·서버 응답에서 실행한다.
세션 내용 보존, 개인 자료의 두 기기 충돌, 비동기 기기 저장 완료/실패,
설정의 동기화 상태 표시, 복구 본문 유무, JavaScript 문법과 앱·서비스워커 버전 일치를 검사한다.
운영 계정이나 서버에 접속하지 않으며 실제 사용자 자료를 사용하지 않는다.
GitHub의 `Storage safety` 검사는 PR과 main 변경 때 같은 명령을 실행한다.
서버의 실제 권한·트리거와 실기기 사용 검증을 대체하지는 않는다.

Playwright와 Chromium이 있는 환경에서는 실제 브라우저 저장도 확인한다.

```bash
node tests/browser/storage-safety.mjs
```

필요하면 `PS_PLAYWRIGHT_MODULE`에 Playwright 모듈 경로,
`PS_CHROME_PATH`에 Chrome 실행 파일 경로를 지정한다.
375px 휴대폰, 1100px 터치 화면, 1280px 데스크톱을 새 브라우저 컨텍스트에서 검사하며,
로컬 테스트 서버 외 요청은 차단한다. 결과와 화면은 `test-results/storage-safety/`에 남는다.

사용법 6개 언어와 시작 안내·설명서의 화면 검증도 별도로 실행할 수 있다.

```bash
node tests/browser/guidance.mjs
```

375px·768px·1100px·1280px 화면에서 언어 전환, 도움말 열기/닫기,
목차 링크와 가로 넘침, JavaScript 예외를 확인한다. 같은 환경변수를 지원하며
결과는 `test-results/guidance/`에 남긴다. 브라우저 검사는 모두 `PS_TEST_OUTPUT`으로 결과 폴더를 바꿀 수 있다.

## 경기 리뷰에서 다음 훈련으로

경기 리뷰의 **다음 훈련으로**에서 개선점을 고르고, 선수에게 보여 줄 행동으로 다듬은 뒤
경기 다음 날 이후의 날짜와 대상 조를 지정한다. 일정의 **경기에서 이어온 과제**를 열어
실행 여부와 관찰 결과를 저장하면 원래 경기 리뷰에서 다시 볼 수 있다.
다음 경기 리뷰에는 이전 14일 동안 다른 경기에서 연결한 완료 과제도 표시한다.

과제는 일정 문서 `process_coach_v1`의 날짜별 `reviewActions`에 고유 ID로 저장한다.
시간순으로 정렬되는 기존 세션과 분리하며, `grp: []`는 팀 공통을 뜻한다.
경기 리뷰 원문 전체를 복사하지 않는다. 코치가 확정한 행동과 관찰 결과는 선수도 읽는 일정 자료다.
일정 편집 권한이 있어야 변경할 수 있고, 신규 연결에는 원래 경기의 편집 권한도 필요하다.
저장 완료는 이 기기의 IndexedDB 확인을 뜻하며 팀 서버 반영은 기존 동기화 상태에서 확인한다.

```bash
node tests/browser/review-training.mjs
```

375px·768px·1280px에서 생성·취소·중복·조별 표시·결과 기록·재로딩·선수 읽기 전용을 검증한다.
가상 부모에 실제 경기 iframe을 열어 CTA 전달, 저장 후 카드 갱신, 정확한 경기 리뷰로 돌아가기도 확인한다.
실제 HTML과 브라우저 저장소에 가상 자료를 넣으며 외부 요청은 차단한다.
결과는 `test-results/review-training/`에 남긴다. Node 회귀에는 실제 화면 함수의 권한·팀 변경,
저장 실패·대기 중 입력 보호, iframe 전달, 기존 일정과의 병합을 포함한다.

## IDP의 첫 행동과 기록 근거

목표의 **내 방향 쓰기**에서 되고 싶은 선수와 이번에 키울 행동 하나를 적고
**저장하고 오늘 기록하기**로 이어간다. 이유와 추가 행동은 선택 사항이며 기존 행동·집중 ID는 유지한다.
목표 내용이 아직 없으면 목표 사다리·장단점·내 무기는 **목표 더 살펴보기**에서 펼친다.

오늘은 기존 주간 초점·12주 문장을 먼저 사용하고, 없으면 내 방향의 집중 행동을 보여준다.
행동 시도와 한 마디를 한곳에 두며, 참여·강도·컨디션·수면 기록은 유지한다.
시도한 문장이 내 방향의 행동과 같고 기존 연결이 없을 때만 당시 행동의 ID·문장·판본을 함께 저장한다.
시도 응답을 바꿔도 기존 장면의 연결은 자동으로 지우지 않는다. 필요하면 **행동 연결 해제**를 누른다.

과거 일간·주간 및 주간 회고에서 저장된 행동과 한 마디를 다시 읽을 수 있다.
당시 방향은 정확히 같은 판본이 남아 있을 때만 표시하며 현재 문장으로 과거를 바꾸지 않는다.
내 방향 저장 충돌은 작성 중인 문장을 화면에 남기며, 취소하면 최신 방향을 확인할 수 있다.

```bash
node tests/browser/idp-start.mjs
```

375px·393px·768px·1280px의 격리된 Chrome과 가상 자료로 첫 행동 설정부터 오늘 기록·재로딩·과거 근거 확인을 검증한다.
동일한 Playwright·Chrome 환경변수를 지원하며 결과는 `test-results/idp-start/`에 남긴다.


## 첫 작업 안내와 파일럿

앱 설정의 **사용법**을 열면 현재 계정·공간·권한에 맞는 **첫 작업 하나 완료하기** 안내가 나타난다.
보드 사용자는 전술 한 장을 만들어 내보내고, 일정 편집이 가능한 코치는 훈련 세션 하나를 저장한 뒤 다시 열어본다.
선수는 내 방향의 행동 하나를 정하고 오늘 기록을 남긴 뒤 같은 날짜에서 확인한다.
안내 버튼은 기존 메뉴를 열며, 안내를 읽거나 클릭한 것만으로 작업 완료를 기록하지 않는다.
로그인·팀·권한이 바뀌면 클릭 전에 안내를 다시 갱신한다. 시작 화면은 기존대로 유지한다.

경기 상세의 현재 위치·날씨 버튼과 GPS·날씨 조회는 제거했다. 경기 진행률과 오늘 화면의 날씨는 유지한다.

제품 이벤트는 전송한 항목의 ID만 확인 처리하여 전송 중 추가된 항목이 사라지지 않게 한다.
기기 큐와 사용 빈도 제한은 계정을 구분하고, 로그인 변경 뒤 다른 계정의 이벤트를 전송하지 않는다.
서버 이벤트 형식은 유지하며, 기기 큐의 소유자·확인 ID는 서버에 추가하지 않는다.
큐의 크기 제한·전송 재시도·일부 행동 억제가 있으므로 이벤트 수를 성공한 작업 수로 해석하지 않는다.

실제 팀 모집이나 파일럿 실행은 아직 하지 않았다. 역할별 관찰 과제, 지표의 분모,
주차별 점검과 다음 개발을 결정할 제안 기준은 [4주 파일럿 계획](docs/pilot-2026-09.md)에 있다.


```bash
node tests/browser/first-work.mjs
```

375px·393px·768px·1280px에서 6개 언어, 실제 셸 메뉴 이동, 로그인·팀·권한 변경 중
이전 버튼 실행 차단을 검증한다. 가상 인증 상태를 메모리에만 두고 외부 요청은 차단한다.
다른 브라우저 검사와 같은 환경변수를 지원한다.

## 훈련 날짜의 개인 초점과 자기보고 강도

세션 채우기와 기존 세션 상세에서 **개인 초점 참고**를 펼치면 선택한 훈련 날짜의 주간 초점과
그 날짜까지 작성된 최신 코치 리뷰를 따로 읽는다. `focusByWk[월요일]`을 먼저 사용하고,
이전 형식의 `focus`는 주가 정확히 같을 때만 사용한다. 코치 리뷰는 참고 기록이며 그 훈련에서
실제로 적용했다는 뜻은 아니다. 현재 목표로 과거 초점을 보완하거나 자동 저장하지 않는다.

대상은 저장된 세션 조 → 하루 조 → 팀 공통 순서와 현재 선수단의 계정 연결을 따른다.
기존 훈련의 빈 `grp` 배열도 하루 조를 상속한다. 이는 경기 리뷰 과제의 `grp: []` 규칙과 다르다.
후보·삭제 선수와 모호한 중복 연결은 제외하며, 실제 출석·과거 조 편성은 추정하지 않는다.
없는 IDP 캐시는 아직 확인하지 못한 자료로 표시한다.

그래프의 계획 부하는 기존 전체 일정의 `RPE × 계획 분`을 유지한다. **선수 자기보고 강도**는
해당 날짜 일지의 유효한 RPE 1~10 평균과 응답 수 / 현재 연결 선수 수를 별도 카드로 표시한다.
조 선택은 이 카드만 바꾸며 일정이나 개인 문서에 쓰지 않는다. 휴식·부상중, 0·범위 밖 값은
평균에 넣지 않고 미응답은 0으로 계산하지 않는다. 실제 참여 시간이 없으므로 계획 분을 곱하거나
계획 부하와의 차이율을 계산하지 않는다. PDF는 계획 자료만 내보낸다.

두 참고 화면은 자료가 준비된 팀 공간의 관리자·운영진·스태프에게만 열리며 계정·팀·권한 변경이나
자료 잠금 때 기존 참고 내용을 지운다. 스태프의 조 필터는 읽기 전용으로 사용할 수 있다.

```bash
node tests/browser/training-context.mjs
```

격리된 Chrome의 375px·393px·768px·1280px에서 현재·과거·미래 주, 저장된 조 상속,
분리된 강도, 잘못된 값, 잠금과 선수 권한, 원본 개인 문서 불변을 확인한다.
같은 Playwright·Chrome 환경변수를 지원하며 결과는 `test-results/training-context/`에 남긴다.
