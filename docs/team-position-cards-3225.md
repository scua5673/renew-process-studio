# 선수단·스카우팅 포지션 카드 3.225

승인된 4열 목업을 기존 선수단·스카우팅 작업 공간에 적용한다. 휴대폰에서도 한 줄 최대 네 포지션을 유지하며 골키퍼는 같은 폭의 독립된 카드로 가운데 배치한다. 스카우팅 이름 아래에는 등록된 소속팀과 등번호를 작은 글자로 표시한다. 명단 보기에서도 같은 정보를 확인할 수 있다.

기존 포지션 ID, 사용자 지정 이름, 선수 배치와 저장된 줄 순서는 그대로 읽는다. GK가 다른 포지션과 같은 줄에 저장되어 있으면 화면에서만 분리하고 원본을 자동 저장하지 않는다. 양쪽 화면은 등록된 선수·후보가 사용하는 포지션과 기존 카드 설정의 합집합을 공유하므로 빈 포지션도 같은 위치에서 볼 수 있다. LCF·RCF는 공격수 역할로 분류한다. 임의의 13개 기본 포지션을 실제 팀 자료에 삽입하지 않는다.

포지션 이동·순서 변경·되돌리기, 기존 상세/평가 편집, 비교와 검색은 기존 경로를 사용한다. 골키퍼 카드에 다른 포지션 카드를 겹쳐 놓는 동작은 거부한다. 이 변경에는 저장 키, 서버/API, 권한, 로그인 또는 DB 변경이 없다.

검증:

- 전체 Node 단위 검사 및 SQL 회귀 검사.
- Chromium·WebKit의 실제 앱 합성 계정: 검색, 상세, 비교, GK/RCB 평가 연결과 기록, 320·390·1100 폭의 네 칸 배치와 중앙 GK, 후보 원문 보존.
- Chromium의 선수 일괄 추가, 선수·포지션 카드 이동, 순서, 되돌리기.
- 실제 휴대폰 모드의 밝은/어두운 화면을 합성 4·4·4·1 구성으로 확인했다. 실제 팀에는 목업 선수나 소속·번호를 추가하지 않았다.
- 실제 휴대폰 기기 및 카카오 인앱 브라우저는 미확인.

배포는 작업 가지 PR → Storage safety 전체 통과 → staging 게시 확인 → 승격 PR → 운영 게시 확인 순서로 진행한다.
