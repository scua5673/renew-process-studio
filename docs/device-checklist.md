# 실기기 점검표 — 배포 전 다섯 흐름

CI 의 WebKit 은 iOS 사파리가 아니다. 맥과 리눅스 WebKit 결과마저 달랐다(2.936). 인계 기록에 «실기기 미확인»이 거의 매 판 남아 있어, **저장·동기화·로그인·셸을 건드린 판**은 아래 다섯 흐름을 실제 기기에서 확인하고 합친다. 화면만 바꾼 판은 바뀐 화면 하나만 해당 기기에서 본다.

## 기기

| 기기 | 브라우저 | 방식 |
|---|---|---|
| 아이폰 | 사파리 — **홈 화면에 추가한 앱**으로 | 세로 |
| 아이패드 | 사파리 — 홈 화면 앱 | 가로 1회 + 세로 1회 |
| 안드로이드 폰 | 크롬 — 설치한 앱 | 세로 |

데스크톱 크롬은 CI 가 대신한다. 한 기기가 없으면 표에 «기기 없음»이라고 적고 넘어간다(통과로 적지 않는다).

## 원칙

- **실제 팀 자료로 시험하지 않는다.** 시험 전용 팀 공간과 시험 계정을 쓴다. 실계정 앱 탭의 저장소를 지우거나 덮지 않는다(2026-09-04 일정 유실 사고).
- 배포 미리보기(PR 의 deploy preview 주소)에서 먼저 본다. main 에 합치면 곧 실사용자 배포다.
- 실패하면 합치지 않는다. 고칠 수 없으면 기능 스위치를 끈 채 내보낸다.

## 다섯 흐름

| # | 흐름 | 통과 기준 |
|---|---|---|
| 1 | 로그인 → 팀 공간 전환 → 다시 개인 공간 | 전환이 끝까지 가고(멈춤·«전환 취소» 없음), 각 공간의 화면이 그 공간 자료만 보인다 |
| 2 | 기기 A 에서 일정 한 칸 고치기 → 기기 B 에서 열기 | 1분 안에 B 에 보인다. A 의 동기화 줄에 «안 올라간 변경» 이 남지 않는다 |
| 3 | 선수 계정으로 일지 «오늘 한 장» 기록 → 앱 닫기 → 다시 열기 | 방금 기록이 그대로 있다. 코치 계정의 선수단 «오늘» 표에 보인다 |
| 4 | 작전판에서 선수 한 명 옮기기 → «보관함 저장» → 보관함에서 다시 열기 | 옮긴 위치가 그대로다. 썸네일에 공·선수가 보인다 |
| 5 | 새 판 적용: 옛 판을 열어 둔 채 배포 → 홈 화면 앱을 다시 열기 | 판 번호(앱 설정 › 기기)가 새 판으로 바뀐다. 입력 중이던 글이 사라지지 않는다 |

## 기록

PR 설명 «검증» 칸에 한 줄씩 남긴다.

```
실기기: 아이폰 15 iOS 18.x 사파리 앱 — 1 ✓ 2 ✓ 3 ✓ 4 ✓ 5 ✓ (판 2.9xx, deploy preview)
```

막힌 흐름은 화면·판·시각·재현 순서를 적고, `docs/pilot-2026-09.md` 의 «저장 신뢰» 지표에 사례로 더한다.
