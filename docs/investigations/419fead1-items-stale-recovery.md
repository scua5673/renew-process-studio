# 419fead1 후속: 오래된 선수 저장 작업의 회차 차단

조사 기준은 3.213, `8a42d0f4d0927eaef048d245d2f92fd4c11bd314`입니다.
기존 자료 불러오기 제보의 후속 안정화이며, 이번 직접 증거는 별도의
`items_write_stale_job` 진단입니다. 이미 처리된 제보의 답글·상태를 바꾸지 않습니다.

합성 계정의 실제 `PSItems.write`가 기준 A를 읽은 뒤 같은 행을 정상 CAS로 B로
진전시키면, 첫 flush는 B를 덮지 않고 거부합니다. 이 보호는 유지해야 합니다.
그러나 이후 입력 없이 공개 `PSSync.syncNow`를 두 번 호출해도 같은 작업이
실패하여 KV 조회가 한 번도 시작되지 않고, 다른 일정도 받지 못했습니다.
이때 상태는 `ok`, `팀과 같아요`, pending 0으로 남았습니다.

수정 전 실제 Chromium fixture는 한 번만 실행했습니다. 제품 수정이나 운영
계정·저장소 쓰기는 하지 않았습니다. 이 문서는 draft PR의 담당 표시입니다.

- 원시 합성 결과 SHA-256:
  `1e6e9be58de6296abf57f06266221340bf08badc74469a16cfc85b49c169ee9d`
- 실행 중인 코드 8개 파일은 전후 동일하며 page error는 0개입니다.
- 새 행 B와 작성 원문을 보존하고, 해당 항목의 미완료를 숨기지 않으면서
  관계없는 일정·보관함 수신을 계속할 수 있는지 확인합니다.
- 단순 예외 무시, 오래된 원문의 새 기준 채택, owner/CAS guard 완화는 하지 않습니다.
- 실제 아이패드 OS 종료의 원인이나 해결을 입증하는 시험은 아닙니다.

최종 변경과 검증 결과는 재현·수정 후 갱신합니다.
