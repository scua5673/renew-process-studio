# 저장·전환·아이패드 안정성 점검

담당 제보: ac40be30 (iPad 종료), cae91d4f (팀 전환).
기준: staging/main 93ebe5addfc116fa51d65daab22df594a77ff2f0 / 공개3.168.
사용자 승인: 저장·복구 → 팀 전환 → iPad 안정성 순서로 개선하고 검증 후 실사용 배포.

## 1. 팀 전환 직전 보드 초안 유실

합성 전체 앱에서 보드를 x450→521로 편집한 뒤 4ms 안에 전환하면, 700ms 초안 타이머보다 전환 guard가 먼저 소유자를 무효화했다. 전환 후 원래 x450이 열리고 LS/IDB 양쪽 초안과 복구 제안이 없어졌다. 개인 보드 서버 쓰기는 없었다.

새 `board-draft.js`가 기존 전환 전 저장 장벽에 연결된다. localStorage는 호출 중 즉시 전체 초안을 쓰고, 공간 부족 때는 IndexedDB 원문 비교 저장과 실제 읽기 확인을 기다린다. 재로드가 선택할 정확한 초안만 완료로 인정한다. 후속 guard 구간에서는 같은 초안이 남았는지 읽어서만 확인한다. 다른 계정·팀·새 편집·경쟁 사본·저장 실패는 전환을 막아 현재 작업을 유지한다. 수동 저장을 서버 자동 저장으로 바꾸지 않는다.

재생 중에는 임시 보간 상태를 원래 편집 상태로 복원한 뒤 확인한다. 숨김/닫기 때의 동기 localStorage 보존, 700ms 기존 타이머와 실패 후 재시도를 유지한다. 미래 시각/경쟁 IDB 사본을 임의로 덮거나 정본으로 선택하지 않는다.

## 2. 보관함 대기 읽기와 숨은 렌더

현재 함수 VM에서 보이는 동안 줄 선 전체 읽기가 실행되기 전에 화면을 닫으면 숨은 상태에서 읽기1회와 결과 반환이 발생했다. 읽기 실행 직전과 완료 뒤에도 실제 화면 상태를 확인한다. 닫힌 뒤 차례가 오면 읽기0회, 진행 중이었다면 결과를 버리고 재진입 때 최신 자료를 한 번 읽는다. 기존 소유자 검사·쓰기 순서·읽기 공유·목록/원문 보존을 유지한다.

## 검증과 한계

- 합성 fixture/VM만 사용하며 실계정 저장소·운영 DB 직접 변경 없음.
- 전체 단위4311, 격리 SQL 전체, runtime1683 묶음 통과. 브라우저 및 정확 커밋 CI/게시 확인은 PR에 최종 결과를 기록한다.
- 숨은 보관함은 Chromium/WebKit375/393/768/1280의 실제 DOM 경합과 재진입을 통과했다.
- 실제 iPad 기기가 없으며 이 경합을 원래 기기 종료의 확정 원인/완전 해결로 표현하지 않는다. 최신 실제 종료 추정 기록은3.131/10월22일10:26 그대로다.
- 원문 없는 `roster_copies_differ`는 보호를 유지한다. 같은 합성 시험 반복으로 해결을 추정하지 않는다.
