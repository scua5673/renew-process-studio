# 3.154 저장 검증 반복 실패 조사

제보 0c4599ff의 긴 선수 이름 회귀 검사가 staging CI39978039672에서 두 번 연속 `board-full-name.mjs:51` 저장 반환값 false로 실패했다. 첫 실패 후 동일한 staging 커밋 4bc087bf의 로컬 WebKit 네 폭 검사는 통과했다. 반복 실패이므로 간헐 실패로 처리하지 않고 원인을 조사한다. 3.154 staging/실사용 게시 보류.

현재 보드 개선 세 건(229361bb, b3c02cfe, 9a418a56)은 PR590으로 staging에 병합돼 있다. 이 후속 PR에서 합성 fixture의 저장 상태와 실패 지점을 확인하고 수정한다. 운영 계정/DB/제보 답변·닫기는 변경하지 않는다.

## 확인한 준비 상태 경쟁 조건

restoreLiveBoard는 로컬 사본을 읽은 직후 _boardPrivateLoaded=true로 바꾸고, 서버 조회는 이후에 기다린다. 최초 부팅의 __boardRestoreDone은 뒤이은 복원 요청 중에도 true라서 기존 검사 조건은 서버 원문 기준이 아직 null인 상태를 허용했다. 합성 fixture에서 두 번째 서버 GET을 붙잡으면 기존 ready=true/current=true/base=null, 첫 저장=false를 재현했고, GET을 풀면 동일 내용이 유지된 채 저장=true였다. 온라인 저장을 검증하는 이 테스트는 현재 계정과 검증된 서버 기준까지 기다린 뒤 선수/장면을 만든다. 앱의 저장 보호 조건과 한 번의 저장 성공·새로고침 검증은 유지한다.

CI의 최초 두 실패에는 당시 내부 상태가 없으므로 그 순간의 원인을 단정하지 않는다. 진단을 추가한 순서 변경 실행은 해당 검사 통과를 확인했으나, 순서 변경으로 해결 처리하지 않는다. 원래 전체 검사 순서를 복원하고 상태 진단을 유지한 채 다시 검증한다. 제품 코드 변경 없음.
