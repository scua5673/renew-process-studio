# 포지션 카드 정렬 개선안

사용자 피드백: 네 칸 폭을 유지하되 한 줄에 두 장만 놓아도 가운데 정렬한다. 같은 규칙을 선수단과 스카우팅에 적용한다.

- 카드 폭은 기존 네 칸 계산을 유지하고 모든 줄을 가운데 정렬한다. 한두세 장인 줄을 너비에 맞춰 늘리지 않는다.
- 카드 높이는 명단 길이에 맞춘다. 짧은 카드에 가장 긴 카드의 빈 공간이 생기지 않는다.
- 편집 모드의 포지션 추가 버튼은 줄 아래에 배치해 카드 묶음의 중심을 밀지 않는다.
- 경기장 배경과 선의 대비를 낮춘다. 후속 요청에 따라 선수단·스카우팅 공통 렌더러에서 줄 위의 FW·MF·DF·GK 구분 글씨를 제거하고 카드 안의 개별 포지션명은 유지한다. 줄의 접근성 이름은 유지한다.
- 스카우팅 카드에서 등번호를 소속팀 옆으로 옮겨 이름 아래 한 줄로 표시한다. 좁은 카드에서는 긴 팀 이름만 줄임표로 줄이고 전체 소속과 번호는 툴팁에 유지한다.
- 원본 명단, 포지션, 배치 순서, 저장 경로는 바꾸지 않는다.

기준 staging b5337681 (3.226). 배포판 3.227. 사용자가 최종 preview-v4 시안을 확인한 뒤 배포를 요청했고, 같은 기준의 최신 staging을 확인했다. 배포 이력과 게시 검증은 workspace outputs/2026-10-31-position-layout/deployment/에 기록한다.

검증: 단위 5,347개 통과. Chromium/WebKit 각각 16개 화면 조건에서 2/3/4/1장 줄의 중앙 오차 1px 미만, 일정한 카드 폭, 가로 넘침 없음, 내용에 맞는 높이, 보기/편집 모드 전환 시 자료 보존을 확인했다. 폭 320·390 모바일 문맥 및 848·1280 데스크톱, 밝은/어두운 테마를 포함한다. Chromium 선수 추가·끌기·되돌리기·포지션 추가 회귀 통과. 실기기는 미확인.

증거: workspace `outputs/2026-10-31-position-layout/`. 비교 화면은 가상 팀의 실제 앱 상단 두 줄이며, 기존 정렬 비교에는 같은 자료에 이전 CSS를 적용했다. 초기 fixture의 기존 평가 설정 보정이 끝난 뒤 자료 보존 검사를 시작한다. 운영 자료를 사용하거나 운영 DB에 쓰지 않는다.

소속팀·등번호 한 줄 표시 후 Chromium 16개 화면 조건을 다시 통과했고 데스크톱·휴대폰 시안 이미지를 갱신했다.

선수단·스카우팅 공통 렌더러에서 줄 구분 span을 제거했다. Chromium 16개 화면 조건 재검증 후 새 파일명 preview-v4.html과 v4 이미지 경로로 이전 시안과 구분했다.

최종 배포 전 단위 5,347개와 WebKit 16개 화면 조건 재검증 통과. 실기기 확인을 대신한 통과로 기록하지 않는다.
