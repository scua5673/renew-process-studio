# 3.234 자동 업데이트 전달

- `update-client.js`가 문서 판·활성 worker 판·배포 manifest를 구분한다. load/복귀/pageshow/online/30분 주기에 확인하며 1분 안의 중복 네트워크 확인은 합친다. worker 질의는 2.5초, manifest는 8초 안에 끝낸다. 게시된 판만으로는 reload하지 않고 활성 worker가 더 새 판임을 확인한 뒤 기존 셸 저장 장벽을 호출한다. 같은 판의 첫 설치는 reload하지 않는다. 등록 실패도 다음 확인에서 재시도한다.
- `sw.js`의 오래 숨은 탭 `navigate()`를 제거했다. 새·옛 문서에 알림만 보내며 현재 문서의 저장 확인을 통과해야 다시 열린다. 예전 문서는 기존 진행 카드와 적용 버튼으로 안내받는다. 응답하지 않는 구버전에 강제 새로고침·캐시 삭제를 하지 않는다. 새 문서 코드를 아직 받지 못한 구버전의 저장 장벽 결함은 이 변경만으로 해결됐다고 말하지 않는다.
- 실제 합성 앱의 비로그인/무편집 상태에서 `flush_fail:fScout:store_ready.sync_workspace_changed`를 재현했다. PSItems foreground가 없는 게스트 계정의 journal을 열려 했다. 계정·팀·기기 소유자가 없고 선수 입력 이력·대기·실행 중 작업도 없는 경우만 no-op이다. 계정이 일시 중단되거나 이전 작업이 있으면 예전 장벽을 유지한다.
- 이 대기를 없애기 전에 게스트 보드에 새 종료 장벽을 연결했다. 수정한 게스트 보드는 기존 기기 저장·원문 readback 후에만 통과하며 저장 중 수정·로그인 변화·열린 편집·I/O 실패는 보류한다. 모든 다른 화면·최상위 공유 큐·계정/팀 seal·workspace lock·20초 timeout은 유지한다.
- 새 진단은 `update_available/downloaded/saving/deferred/check_failed/install_failed/applied`. 기존 `PSSync.event`만 사용한다. 작성 내용·오류 원문·인증정보 없이 판·단계·코드·일시적인 업데이트 ID·경과 분을 기록한다. 로그인 없는 관찰은 나중 계정에 넘기지 않는다. 같은 단계·코드·판은 5분 제한이다. 이전 `update_deferred` 진단도 구버전 비교를 위해 유지한다.
- 관리자 `업데이트 적용 지연`은 기존 관리자 전용 ps_events 읽기로 최근 48시간 최대 4000줄을 페이지 조회한다. 최근 2시간에 신호가 있으며 관찰된 지연이 10분 이상인 미완료 세션, 또는 확인/설치 실패를 보여준다. 적용 완료는 동일 사용자·업데이트 ID·목표 판에만 연결한다. 물리 기기 수·현재 온라인 여부·전체 적용률로 해석하지 않는다. 조회 상한/실패는 명시한다. 오래된 20판 기준 목록은 참고용으로 접어 두었다. DB/RLS 변경 없음.

검증: 단위/기존 저장 회귀 + 실제 SW 2개 버전의 첫 설치, 저장 실패 보류, pageshow 복귀, 저장 후 reload, 설치 실패 시 이전 판 유지, online 재시도. 합성 앱 게스트 무편집 통과·편집 저장 실패·재시도·재열기 내용 보존. Chromium/WebKit으로 검사하며 실제 iOS/Android 홈 화면 앱은 별도 기기 검증이다.

운영: 제보자에게 먼저 막힌 화면의 기기 저장 상태를 확인한다. 저장 확인 전에 앱 강제 종료·캐시 삭제·재설치를 안내하지 않는다. 아주 오래된 판은 새 코드가 실행되지 않으므로 저장 확인 후 정상 재실행이 한 번 필요할 수 있다.
