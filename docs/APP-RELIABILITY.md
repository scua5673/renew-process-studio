# 앱 안정성 작업 기준 — 2027년 1월 목표

범위는 PROCESS STUDIO 앱의 정상 작동이다. 결제 작업은 포함하지 않는다.

## 이번 수정

- 여러 명 추가의 입력 확정 때, 바뀌지 않은 합계와 확인 버튼 글자는 다시 쓰지 않는다. WebKit에서 첫 클릭이 사라지는 재현을 막는다. 저장 실행은 기존 클릭 경로 하나다.
- 포지션 판의 자동 선택은 자료가 도착하면 실제 명단을 따라간다. 직접 고른 포지션은 비어 있어도 유지하며, 빈 안내는 해당 범위만 설명한다.
- 선택된 B안: 휴대폰 세로 선수단은 명단으로 시작한다. 인원 요약과 수정 정보는 기본으로 접고, 자세히에서 기존 내용과 조작을 그대로 펼친다. 넓은 화면에서는 원래 헤더 위치로 돌린다.

## 통과를 판단하는 방법

화면 반영, 기기 저장 확인, 새로고침 복원, 서버 수락, 다른 기기 수신은 각각 따로 확인한다. 대기 수가 0이라는 이유로 다른 단계가 끝났다고 하지 않는다.

| 흐름 | 필요한 확인 |
|---|---|
| 선수단·스카우팅 | 실제 클릭/터치로 추가·편집·검색·조/포지션 변경·취소, 정확히 한 번 저장, 다시 열기 |
| 일정 | 일간 작성→주/월 보기→복제→훈련 열기→다시 열기, 원본과 복사본 독립 |
| 작전판·보관함 | 편집→명시 저장→다시 열기, 페이지·장면·선수 위치·이름 보존 |
| IDP·권한 | 선수 자기 기록 보존, 코치 평가 비공개, 다른 팀/계정 자료 접근 차단 |
| 실패·복구 | 용량 초과·IDB 실패·응답 지연 때 성공 오표시 없음, 새 입력 보존, 재시도·전환 장벽 |
| 업데이트 | 입력 중 업데이트 보류, 저장 확인 뒤 새 판 적용, 재시작 후 자료 유지 |

## 진행 순서

1. 현재 재현된 결함의 수정과 브라우저 검증. 변경마다 작은 PR과 실패 원본을 남긴다.
2. 매일 오전 10시 순환 사용 점검. 새 증거와 새 문제만 피드백하고, 통과한 검사를 이유 없이 반복하지 않는다.
3. 11월에는 위 여섯 흐름의 실제 사용자 입력 검사를 보강하고, 합성 서버가 선수별 쓰기 API까지 재현하는지 확인한다. 단위/합성 SQL 성공은 운영 DB 적용 증거가 아니다.
4. 12월에는 기능 변경을 줄이고 실제 아이폰·아이패드·안드로이드 설치 앱 및 두 기기 간 수신·업데이트·복구를 확인한다. 결과는 docs/device-checklist.md 형식으로 기록한다.
5. 1월 전 최종 판단은 해결되지 않은 데이터 손실/저장/권한 결함, 실기기 결과, 운영 복구 근거를 보고 한다. 날짜나 검사 개수만으로 정상 작동을 보장하지 않는다.

실기기와 운영 복구 확인을 합성 브라우저·메모리 DB 검사로 대신 표시하지 않는다. 실제 사용자 자료를 시험용으로 바꾸지 않는다.
