# 펼친 폴드 보드와 도구 표시 — 3.232

오류 제보의 핵심은 애니메이션·콘/마커를 찾기 어렵고 도구창이 운동장을 가리는 것이다. 기존 보드·저장 방식·도구 노드를 유지한다. 사용자 확인에 따라 넓게 펼친 폴더블에는 편집을 허용하며 일반 휴대폰과 접힌 화면은 보기 전용으로 둔다.

## 변경

- `board-phone-view.js`: 휴대폰 정체성과 현재 편집 가능 여부를 분리한다. 최상위 실제 화면의 짧은 변과 창 너비가 모두 600 CSS px 이상일 때만 펼친 화면으로 인정한다. iframe의 확대된 논리 폭이나 일반 폰의 가로 회전만으로는 편집을 허용하지 않는다. 화면 정보가 없으면 기존 보기 전용으로 남는다. 키보드 때문에 창 높이가 줄어도 편집 여부는 바뀌지 않는다.
- `app.html`, `board.html`: 현대 보드의 접기·펼치기에서는 문서를 새로 불러오지 않는다. 늦게 펼쳐도 기존 도크를 장착한다. 768px 미만의 펼친 화면은 보드 프레임만 논리 768px로 맞추고, 실제 하단 메뉴 위까지 높이를 제한한다. 펼친 휴대폰에서 부모 영역 크기가 바뀌면 다시 측정한다.
- `board-dock-float.js`: 선수·훈련 도구·애니메이션에 이름을 붙이고 열림 상태를 표시한다. 도구창 닫기와 전체 도구 접기/펼치기를 제공한다. 좁은 편집 화면에서는 간격을 줄여 설정 버튼까지 화면 안에 넣는다. 장면·선수 데이터는 표시 전환으로 수정하지 않는다.
- 기존 보관함·커뮤니티·작성자 권한 보호와 저장 경로는 유지한다. 휴대폰에서 보기 전용으로 연 자료를 펼친다고 원본의 별도 읽기 전용 권한을 해제하지 않는다.

## 검증

- 단위 검사 5,356개 통과. 화면 판정, 일반 폰 가로/데스크톱 보기, 키보드 높이, 하단 메뉴와 보드 높이 회귀 검사를 포함한다.
- `npm run test:sql` 통과. 네트워크 없는 PGlite 검사이며 운영 DB 변경 없음.
- Chrome에서 합성 사용자·로컬 서버로 실제 UI를 조작했다. 1088×759 / 759×1088 / 400×900 전환, 접힌 상태에서 시작 후 18초 이후 펼치기, 도구창 열기/닫기, 애니메이션 열기/닫기, 전체 접기/펼치기를 확인했다.
- 선수 드래그 후 미저장 상태로 접었다 펼쳐 선수·장비·그림·장면 스냅샷의 내용 보존을 확인했다. 접힌 상태의 명시 저장은 false, 펼친 상태의 저장은 true였다. 다시 열어 이동한 선수 좌표(472.745758, 356.440674)와 3개 장면이 복원됐다.
- 일반 휴대폰의 실제 화면 400×900을 유지한 채 창을 900×400 및 넓은 데스크톱 크기로 표시해도 보기 전용이었다. 드래그 후 내용 비교는 동일했고 저장 호출은 거부됐다.
- 세로 폴드 도구 행의 보이는 모든 단추가 논리 화면 안에 있고 하단 탐색 메뉴와 겹치지 않음을 DOM 좌표와 스크린샷으로 확인했다.
- `tests/browser/fold-board-tools.mjs`를 selection CI 목록에 추가했다. 해당 자동 브라우저 파일의 구문 검사는 통과했으며, 로컬에서는 CUA를 통한 실제 Chrome 조작으로 위 시나리오를 확인했다. Chromium/WebKit에서 폴드 편집·저장 검사는 통과했다. 전체 CI에서 발견한 좁은 커뮤니티 화면의 도크 여백 반복 계산과 휴대폰 단일 페이지의 클릭 영역 회귀를 수정했으며 최종 전체 CI를 다시 확인한다.

- 커뮤니티를 1280×960 → 1100×820 → 375×812로 바꾼 뒤 훈련을 전환해도 응답하고 보드가 표시되는 것을 Chrome에서 확인했다. 커뮤니티의 편집 도크는 화면 폭과 관계없이 감추며, 기존 자동 검사에도 이를 명시했다.

## 남은 확인과 상태

실제 폴더블 기기에서는 브라우저가 펼침 전후 `screen.width/height`를 어떻게 보고하는지와 터치·키보드 동작을 확인해야 한다. 특정 모델 전용 판을 복제하지 않았으며, 기기명으로 지원을 보증하지 않는다.

로컬 검증 완료 당시에는 푸시·PR·배포를 하지 않았다. 이후 2026-11-01 사용자가 오류 제보 답변과 실사용 배포를 명시적으로 승인했다. 실기기는 없는 상태임을 승격 PR에 기록하고 CI·시험 사이트 확인 후 승격한다. 대상 제보는 987d756f-e6e7-4790-b898-b4d98bd1dae7이며, 배포 완료 확인 뒤 고친 판을 기록하고 닫는다.

스크린샷과 검사 로그는 작업 공간의 `outputs/2026-11-01-board-tools-consistency/`에 있다. 합성 검사 도구·가상 팀은 제품 코드에 포함되지 않는다.
