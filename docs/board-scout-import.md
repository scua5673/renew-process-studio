# 보드에서 스카우팅 명단 불러오기

사용자 요청: 팀 운영의 스카우팅 후보 명단을 보드로 가져오기.

보드 설정 → 배치 → 스카우팅 명단 → 불러오기에서 후보를 선택하고 팀 1 또는 팀 2에 배치한다. 검색(이름·소속팀·등번호), 영입 단계·포지션 필터, 표시된 후보 선택·전체 해제를 제공한다. 같은 후보의 여러 포지션 배치는 한 명으로 표시한다. 보관·삭제 후보는 기존 스카우팅 화면과 같은 규칙으로 제외하고 미배치 후보는 포함한다.

`board-scout-import.js`는 기존 `PSScoutStore.createClient().prepare/check`로 현재 계정·팀·운영진 권한과 후보 원문을 확인한다. 선수단은 IDB와 화면 사본의 일치를 확인하고, 삭제 기록은 storage-keys.js에 선언된 LS 원본만 읽는다. 일반 선수단·삭제 기록에는 `keyReady` 표가 발급되지 않으므로 후보 문서의 준비 표와 동일하게 취급하지 않는다. 명단을 연 뒤 팀·권한·원문이 바뀌면 가져오기를 중단한다. 보기 전용·휴대폰 보기 전용·재생 중에는 실행하지 않는다.

보드에는 이름·등번호·포지션만 복사한다. 스카우팅 평가·메모·사진·원본 명단은 저장하지 않는다. 기존 `PSTeamLoad.plan/dress/frames`, `pushUndo`, `autoSaveAnimFrame`, `boardSaveLive`를 사용한다. 기존 토큰 ID·위치·크기를 유지하고 초과 인원은 대기 줄로 배치한다. 현재 팀 유니폼과 상대 팀은 그대로다. 다른 장면·페이지와 미팅 리저브의 적용 범위도 기존 저장 팀 불러오기 규칙을 따른다. 보드의 명시적 저장 동작을 유지한다. `n2u`, `uid`, `state` 등은 window 속성이 아닌 전역 lexical binding이므로 직접 참조한다.

검증은 운영 데이터와 분리된 합성 팀 fixture에서 수행한다. `tests/board-scout-import.test.cjs`는 원장 투영·중복·삭제·검색·읽기 실패·원문 변경을 검사한다. `tests/browser/board-scout-import.mjs`는 실제 버튼 클릭, 필터/선택, 검색 Enter, 취소, 14명 배치, 위치 보존, 실행 취소/다시 실행, 두 팀, 다른 장면, 명시적 저장, 권한·원문 변경, 보기 전용을 Chromium과 WebKit에서 검사한다. 브라우저 CI board 묶음에 포함했다.

현재 준비 판은 3.240이며, 병합 전에 최신 staging과 병렬 작업의 판 번호를 다시 확인한다. 아직 원격 push·PR·운영 배포는 하지 않았다.
