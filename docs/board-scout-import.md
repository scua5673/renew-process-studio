# 보드에서 스카우팅 명단 불러오기

사용자 요청: 팀 운영의 스카우팅 후보 명단을 보드로 가져오기.

보드 설정 → 배치 → 스카우팅 명단 → 불러오기에서 후보를 선택하고 팀 1 또는 팀 2에 배치한다. 검색(이름·소속팀·등번호), 영입 단계·포지션 필터, 표시된 후보 선택·전체 해제를 제공한다. 같은 후보의 여러 포지션 배치는 한 명으로 표시한다. 보관·삭제 후보는 기존 스카우팅 화면과 같은 규칙으로 제외하고 미배치 후보는 포함한다.

`board-scout-import.js`는 기존 `PSScoutStore.createClient().prepare/check`로 현재 계정·팀·운영진 권한과 후보 원문을 확인한다. 선수단은 IDB와 화면 사본의 일치를 확인하고, 삭제 기록은 storage-keys.js에 선언된 LS 원본만 읽는다. 일반 선수단·삭제 기록에는 `keyReady` 표가 발급되지 않으므로 후보 문서의 준비 표와 동일하게 취급하지 않는다. 명단을 연 뒤 팀·권한·원문이 바뀌면 가져오기를 중단한다. 보기 전용·휴대폰 보기 전용·재생 중에는 실행하지 않는다.

보드에는 이름·등번호·포지션만 복사한다. 스카우팅 평가·메모·사진·원본 명단은 저장하지 않는다. 기존 `PSTeamLoad.plan/dress/frames`, `pushUndo`, `autoSaveAnimFrame`, `boardSaveLive`를 사용한다. 기존 토큰 ID·위치·크기를 유지하고 초과 인원은 대기 줄로 배치한다. 현재 팀 유니폼과 상대 팀은 그대로다. 다른 장면·페이지와 미팅 리저브의 적용 범위도 기존 저장 팀 불러오기 규칙을 따른다. 보드의 명시적 저장 동작을 유지한다. `n2u`, `uid`, `state` 등은 window 속성이 아닌 전역 lexical binding이므로 직접 참조한다.

검증은 운영 데이터와 분리된 합성 팀 fixture에서 수행한다. `tests/board-scout-import.test.cjs`는 원장 투영·중복·삭제·검색·읽기 실패·원문 변경을 검사한다. `tests/browser/board-scout-import.mjs`는 실제 버튼 클릭, 필터/선택, 검색 Enter, 취소, 14명 배치, 위치 보존, 실행 취소/다시 실행, 두 팀, 다른 장면, 명시적 저장, 권한·원문 변경, 보기 전용을 Chromium과 WebKit에서 검사한다. 브라우저 CI board 묶음에 포함했다.

배포 판은 3.242이다. 최신 staging/main의 작전판 배치·그리드 3.240을 병합해 보존했다. 사용자 배포 승인에 따라 정식 PR → testprocess → main 경로로 검증·게시한다.

## 추가 요청: 선수단·훈련 편집기와 조 변경

보드 설정 → 배치 → 명단 불러오기에서 **선수단 / 스카우팅**을 고른다. 훈련 편집기의 인원 카드 아래에도 같은 두 버튼을 둔다. 선수단은 이름·번호·포지션·조로 검색/필터하고 필요한 선수만 선택한다. 팀 원본 `scout_tool_v1`과 삭제 기록을 읽기만 하며 IDB 일치·계정·팀·역할·캐시 소유자를 재확인한다. 후보 조회 권한과 선수단 조회 권한은 각 원본의 경계를 유지한다. 보드 편집 권한 및 훈련 읽기 전용 상태도 적용 직전에 확인한다.

훈련에서 불러오면 선택 명단의 상태에 따라 GK·필드·재활·부상/불참을 기존 `syncEpRosterUI`로 채운다. 인원은 선택한 명단으로 교체하며, 보드에는 선택한 선수 모두를 표시한다(기존 ‘전체 선수’와 같은 처리). 후보 영입 단계는 선수 출결 상태로 쓰지 않는다. 훈련 저장/재열기는 원래 카드의 roster와 snap 경로다. 불러오기 도중 편집 대상이 바뀌면 창을 닫는다. 보드 토큰의 실행 취소는 원래 경로를 유지하며 훈련 인원 입력은 기존 인원 저장 동작을 따른다.

선수단 포지션 판의 **조 변경**을 켜면 선수 이름 아래 현재 조를 표시하고, 이름을 눌러 기존 `grpPickOpen`의 기본·사용자 조·없음 중 고른다. 해당 모드에서는 끌기를 멈추고 판 편집과 상호 배타로 둔다. 조 변경 후 포지션·순서·다른 선수 필드는 그대로이며 `save({skipTargets:true})`와 `renderTeam`을 사용한다. 선택창을 연 뒤 계정·팀·권한·명단 객체·해당 선수·이전 조가 바뀌면 적용하지 않는다. 선택 모드는 저장하지 않는다. 저장 실패를 완료로 알리지 않는다.

추가 검증: `board-roster-import`는 두 엔진에서 조 필터·9명 선택·원본 불변·훈련 18명 인원 분류·후보 배치·취소·실제 훈련 저장/재열기·보기 전용을 검사한다. `squad-group-change`는 두 엔진의 데스크톱/휴대폰 문맥에서 조/사용자 조/없음, 필터에서 빠짐, 권한/원문 변경 차단, Escape 초점 복원, 새로고침 유지와 임시 모드 해제를 검사한다. 기존 `squad-depth-drag`는 모드 해제 시 끌기의 회귀를 확인한다.

배포 CI의 WebKit 조 변경 검사는 저장 후 새로고침하여 선수단에 다시 진입할 때 숨겨진 버튼으로 대기했다. `sendTeamView`에서 먼저 예약한 오늘 화면의 load 콜백이 나중의 선수단 선택을 덮을 수 있음을 실제 함수를 실행하는 단위 검사로 재현했다(수정 전 6개 중 5개 실패). 별도 PR739의 이 부분만 검토해 프레임별 요청 번호·현재 메뉴를 확인하는 두 줄과 행동 검사 6개를 포함했다. PR739의 저장 상태 테스트·버전 변경은 포함하지 않는다. 명단 저장 확인 단정이나 대기 제한을 완화하지 않는다.

추가로 같은 새로고침 흐름에서 요청 번호 2인데 선택 메뉴가 today로 돌아간 상태를 기록했다. 명단의 비동기 초기화가 끝나며 `init()`이 항상 home을 열던 경로다. 부모 프레임의 일시적인 최신 요청 화면을 초기화가 읽어 유지한다. 저장 키는 추가하지 않으며 독립 실행은 home, 평가 항목 딥링크는 attrs를 유지한다. 화면 요청·초기화 9개 행동 검사와 기존 재열기 단정으로 검증한다.

초기 `teamViewNow(home)` 알림이 부모의 선택을 today로 바꾸고 새 요청을 취소하는 경로도 실제 부모 핸들러 실행으로 재현했다. 요청을 보내기 전에는 이 초기 알림으로 메뉴를 덮지 않으며, 요청 적용 이후 화면 안의 이동은 원래대로 메뉴에 반영한다. 두 보호와 초기 화면 선택을 함께 검증한다. 브라우저 시험은 준비 시점 대기를 추가하거나 저장·재열기 단정을 약하게 하지 않았다.

배포 도중 병합된 PR743의 훈련 도구 영역 수정(3.241, staging92a3c4cf)도 통합했다. 두 변경 안내와 두 브라우저 검사 목록을 모두 유지하며 최종 앱 판은 3.242다.

통합 CI의 명시 보드 저장 실패는 시험 서버의 UTF-8 분할 오류로 재현했다. HTTP Buffer 조각마다 문자열로 바꾸어 더하던 fixture가 `장도현`을 `장���현`으로 바꾸었고, 런타임의 서버 원문 완전 일치 검사가 정상 거절했다. 조각을 Buffer로 합친 뒤 한 번 디코딩하도록 시험 서버만 수정했다. 모든 바이트 경계의 한글·이모지, 빈 요청, 중단 요청 검사를 추가했으며 저장 성공 단정과 원문 검증은 유지한다. 운영 저장 코드·SQL은 변경하지 않았다.

WebKit 휴대폰의 권한 상실 시험은 잠금 뒤 다시 그려질 때 정상적으로 닫힌 고르개를 Playwright가 누르려고 기다리는 경합이 있었다. 잠금 직후 이미 대기하던 클릭과 다시 그려져 분리된 버튼의 지연 클릭을 각각 실행해 명단 불변을 검증한다. 잠금 상태의 고르개·편집 버튼 제거와 권한 복원 뒤 임시 모드 해제도 확인한다. 정상 조 변경은 실제 클릭/탭 및 저장·새로고침 검사를 그대로 유지하며 앱 런타임은 바꾸지 않는다.
