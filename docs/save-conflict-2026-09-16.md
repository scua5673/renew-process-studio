# 오류 제보 전체 조사 및 수정

상태: 2.842 수정·로컬 검증 완료, PR 미리보기 및 운영 배포 검증 예정.

## 전체 제보 확인

관리자 오류 제보 목록의 3건을 모두 확인했다. 추가 페이지는 없었다.

- 저장 문제: 반복되는 조건부 저장 충돌을 조사하고 아래 저장 확인 경로를 수정했다.
- 팀 운영에서 경기 부분 클릭이 안됩니다: 선발 설정 후 국면 편집이 막힌다는 내용이다. 첫 제보와 오류 시각이 겹쳤고, 다른 키의 저장 실패가 이미 확인된 경기 편집까지 잠그는 경로를 재현했다.
- 안녕하세요 테스트입니다: 테스트 접수 확인 요청이다. 별도 기능 장애 증상은 없었다. 첨부된 오래된 진단에는 정상 사본 정리와 사유가 없는 일반 오류가 있어, 일반 오류의 원인은 해당 제보만으로 특정하지 않았다.

## 확인한 사실

- 제보 버전은 2.841이며 Safari/macOS에서 반복되는 `sync_conflict`로 저장 완료를 확인하지 못했다.
- 관리자 화면에서 제보 시각과 일치하는 `kv_push_cas` / `server changed during import` 오류를 확인했다.
- 해당 기기 보고에는 개인 공간 대기 2건, 보류 0건, 충돌 검토 0건이 표시됐다. 이 값은 기기의 보고이며 서버 저장 완료의 독립 검증은 아니다.
- 배포된 `studio/sync.js`와 수정 전 HEAD 파일의 SHA-256이 일치했다: `e551f5e04fe56610b9802af2698880ab16883840959cf7f143c930ea17301938`.
- `copies-purged`는 기존 기기 사본 정리의 완료 진단이다. 이번 저장 실패의 원인이라는 근거는 없다.

## 재현과 수정

1. 서버 메타 목록에 기존 행이 누락되면 매 회차 중복 방지 INSERT가 빈 응답을 돌려주며 충돌이 반복됐다. 이제 기기에 자료가 있는 해당 키를 직접 조회한 뒤, 실제 서버 판본을 기준으로 처리한다.
2. 조건부 저장 응답이 빈 배열이면 실제 저장 여부를 확인하지 않고 충돌로 처리했다. 이제 같은 공간·키의 서버 원문과 판본을 다시 읽는다. 본문이 정확히 같을 때만 실제 서버 판본으로 확정한다.
3. 본문이 다르면 저장을 확정하지 않는다. 서버 판본이 그대로인 거부와 실제 다른 판본의 충돌을 구분한다. 확인 실패·잘못된 응답·계정 전환은 대기를 유지한다.
4. 저장 상태에 충돌과 서버 거부를 구분해 표시하고, 반복 시 오류 제보 안내를 제공한다. 제보에는 고정된 실패 단계만 보존하며 정상 사본 정리 이벤트는 오류 목록에서 제외한다.
5. 경기 선발 저장이 성공한 뒤 다른 키의 저장이 실패하면 경기 편집 준비표까지 닫힌 채 반복되었다. 실패 회차에서도 경기 서버 확인 원문·IndexedDB·화면 사본이 정확히 일치하는지 재검증하여 경기 준비표만 복구한다. 전체 저장 메타·다른 키의 대기 상태는 성공으로 바꾸지 않는다. 계정·공간 전환, 새 편집, 저장소 실패, 경기 자체의 거부는 계속 차단한다.

조건부 쓰기를 무조건 덮어쓰기로 바꾸지 않았다. 운영 자료·권한·DB 스키마는 변경하지 않았다.

## 남은 확인

운영 로그는 실패한 자료 키와 서버 응답 본문을 포함하지 않으므로, 제보 기기가 위 재현 조건 중 어느 경우인지는 확정하지 못했다. 실제 서버 권한·보호 규칙이 쓰기를 거부하는 상황 자체는 이 클라이언트 수정으로 해제되지 않는다. 배포 후 제보 기기의 대기 해소와 저장 확인을 점검해야 한다. 제보자에게는 아직 답변을 전송하지 않았다.
