# 프로세스 레터

사용자 결정(2026-10-26): 프로세스 탭에 준비된 46호를 전부 표시하며, 레터를 누르면 본문과 관련 훈련을 읽는다. 예약 날짜를 기다리지 않는다. 공개 레터 사이트 자체의 발행 일정은 바꾸지 않는다.

- `studio/letters/index.json`: 호수, 제목, 소개, 글과 훈련 제목. 목록을 열 때 이 작은 색인만 읽는다.
- `studio/letters/NN.json`: 편집 원문의 전체 사본. 읽을 때 한 호씩 받는다. 소개·좋은 팀/선수/코치 세 글·출처·인용문·맺음·훈련 본문을 보존한다.
- `studio/community-letters.js`와 `.css`: 단일 세로 목록, 제목·호수·관련 훈련 검색, 최신호/1호 순서, 본문과 목차, 읽던 목록으로 돌아가기.
- 관련 훈련은 호 번호로 기존 `procFind → procOpen → procEnsure`와 연결된다. 앱이 보강한 로컬 팩을 우선하고, 기존 읽기 전용 작전판·훈련 선택·보관함 확인 창을 사용한다. 새 게시물이나 동기화 키를 만들지 않는다.
- 1호에는 훈련이 없으므로 읽기만 제공한다. 훈련이 있는 2~46호는 각 3개, 총 45세션·135훈련이다.
- 기본 정렬은 1호부터이며 최신호순으로도 바꿀 수 있다. 본문이 정상적으로 표시된 호에만 `✓ 읽음`을 붙인다. 실패하거나 화면을 떠난 뒤 도착한 응답은 읽음으로 세지 않는다.
- 읽음 기록은 `ps_comm_letters_read_v1:<uid|guest>`에 호 번호만 저장한다. 새로고침·재방문에도 유지하며 로그인 계정과 비로그인 기록은 분리한다. 같은 브라우저의 탭끼리 반영하지만 기기 사이에는 동기화하지 않는다. 저장소를 쓸 수 없으면 현재 화면에서만 유지한다.

원고 정본은 프로세스 레터 사이트의 `site/src/issues`다. 이 앱의 원고 사본을 따로 편집하지 않는다. 원고를 갱신할 때:

```sh
node scripts/import-community-letters.mjs <레터-사이트>/src/issues
```

가져오기는 정본을 읽기만 하며, 훈련 팩의 호 번호와 훈련 수가 맞지 않으면 쓰기 전에 중단한다. 새 호에 훈련이 있으면 해당 팩과 썸네일도 먼저 준비한다. 파일을 Git에 추가한 뒤 앱 버전을 올려 배포한다.

검증은 `tests/community-letters.test.cjs`(46호 원문·훈련 연결·검색·출력 안전성), `tests/browser/community-process.mjs`(읽기·오류 재시도·늦은 응답·훈련 재생·보관함), `tests/browser/community-library.mjs`(화면 크기와 테마)에서 한다.
