# 레터 독자·반응 집계

1. preflight.sql: auth 및 두 역할이 준비되어 있는지 확인한다. 같은 이름의 기존 표가 있으면 이 마이그레이션의 구조와 맞는지 먼저 확인한다.
2. local-test.cjs를 실행한다. 반복 열람·좋아요 취소·계정 전환·비로그인에서 로그인 전환·접근 권한을 검증한다.
3. .sql 적용 후 .verify.sql의 모든 검증이 참이고 public_letters가 46인지 확인한다. 공개 표에 개인의 기록을 직접 읽고 쓰는 권한은 없다.
4. 앱/공개 레터 페이지에서 독자 수·좋아요·공유를 확인한다. 본문은 집계 API가 실패해도 읽을 수 있어야 한다.
5. 적용 결과를 .applied.md로 남기고 scripts/schema-baseline.mjs로 기준본을 갱신한다.

집계는 적용 이후부터 시작한다. 로그인은 계정, 비로그인은 무작위 브라우저 식별자 기준이다. 앱은 본문을 5초 이상 보였을 때 읽음을 보낸다. 쿠키/저장소 삭제, 다른 브라우저, 새 익명 식별자를 생성하는 조작까지 같은 사람으로 식별할 수는 없다. 공개 숫자는 인증된 사람 수나 이메일 발송 수가 아니다. 서비스 이용자의 이름·이메일·IP는 이 표에 저장하지 않는다. 비로그인 식별자는 저장소가 차단되어 있으면 생성하지 않아 새로고침마다 숫자가 늘지 않도록 한다.

되돌리기: 이전 프론트로 복구하고 rollback.sql로 함수 실행만 차단한다. 수집한 수치는 지우지 않는다. 이 마이그레이션을 재적용하면 권한을 복원한다.
