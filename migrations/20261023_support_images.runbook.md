# 오류 제보 이미지 첨부 설치

제보 `93a76051-3643-4e7e-88f0-c650bceb5a93` · 앱 3.153 · PR #588.

## 적용자와 순서

운영 DB 변경은 사람이 Supabase SQL Editor에서 실행한다. 프로젝트는 `jvtajoeptzfsdwizxejg`이다. testprocess와 processstudio는 같은 DB를 사용하므로 한 번만 설치한다. 앱은 기존 글 제보를 계속 사용할 수 있다.

1. `20261023_support_images.preflight.sql` 전체를 실행한다. 오류가 나면 멈춘다.
2. `20261023_support_images.sql` 전체를 실행한다. 하나의 트랜잭션이며, 실패하면 새 변경 전체가 취소된다. 기존 제보·답변·RPC 정의는 수정하지 않는다.
3. `20261023_support_images.verify.sql` 전체를 실행한다. 결과가 `support-images-v1-ready`여야 한다. 이 검사는 읽기 전용이며 실제 제보를 만들지 않는다.
4. 적용 시각·검사 결과를 담당자에게 알려 준다. 담당자는 읽기 전용으로 재확인하고 schema baseline을 갱신한 뒤, CI와 staging 검증을 통과한 앱을 승격한다.

예상과 다른 이름의 테이블/함수가 이미 있으면 덮어쓰지 않고 중단한다. 같은 설치 파일은 다시 실행할 수 있다. 임시 관리자 토큰이나 실제 이미지 내용을 기록에 붙이지 않는다.

## 저장과 접근

- 최초 제보에 정지 이미지 한 장. 기기에서 최대 2048px·512KiB JPEG로 다시 인코딩한다. 원본 파일은 10MiB·1,200만 화소 이하여야 한다.
- 별도 비공개 테이블 `ps_support_images`에 저장한다. 공개 버킷·공개 URL을 만들지 않는다. 기존 제보의 작성자와 플랫폼 운영자만 RPC로 읽는다. 팀 운영자 권한만으로는 볼 수 없다.
- 글과 이미지가 하나의 트랜잭션으로 등록된다. 같은 ID·글·진단·이미지로 재시도하면 기존 접수 결과를 돌려준다. 값이 다른 재시도는 충돌로 남긴다.
- 이미지가 있는 새 제보는 계정당 최근 24시간 20건까지다. 이미 등록된 동일 요청의 재확인은 한도와 무관하게 허용한다.
- 목록에는 이미지 본문이 없다. 상세의 ‘첨부 이미지 보기’를 누를 때만 가져온다. 복사·로그·팀 동기화에는 이미지 바이트를 넣지 않는다.
- 임시 이미지는 계정별 기기 IDB에 최대 한 장 보관한다. 접수 확인 후 지운다. 저장 실패 시 현재 창의 원본을 유지하고 안내한다.
- 이미지 보존 기간은 제보와 같다. 제보를 닫아도 보관하며, 제보 행을 삭제할 때만 연결 이미지가 함께 삭제된다. 자동 만료는 이번 범위에 없다.

## 되돌리기

`20261023_support_images.rollback.sql`은 새 RPC만 제거한다. 이미지와 제보를 삭제하지 않는다. 이미지 없는 제보는 계속 사용할 수 있고, 새 이미지 접수 실패 시 글과 이미지를 화면에 보관한다. 다시 설치하면 기존 이미지도 재열람할 수 있다. 기존 이미지 테이블을 수동 DROP하지 않는다.

## 검증

- 합성 PGlite SQL: 직접 테이블 접근 차단, 작성자/운영자 허용, 타인/팀 관리자 거부, 멱등 재시도·충돌, 이미지 크기/형식/일일 한도, 잘못된 입력의 원자적 거부, 설치 두 번·안전한 rollback/reinstall.
- 브라우저: 실제 이미지 압축·미리보기·삭제, IDB 저장 실패 보존, 전송 전 실패와 서버 접수 후 응답 유실/새로고침/재확인, 관리자 열람과 계정 변경. Chromium/WebKit, 375·393·768·1280px.
- 모든 검증은 합성 자료와 차단된 외부 네트워크에서 한다. 운영 DB에 테스트 제보를 쓰지 않는다.
