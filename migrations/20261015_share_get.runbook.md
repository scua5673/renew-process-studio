# 20261015 — 링크 공유(ps_share)를 «아는 id 한 건»으로만 읽기

## 왜

짧은 공유 링크 `/s/<id>` 는 익명 키로 `ps_share` 테이블을 직접 읽었다(`app.html __shareBoot`). RLS 는 요청의 `id=eq.` 필터를 볼 수 없으므로,
익명이 한 행을 읽을 수 있으면 같은 키로 **모든 공유본**을 내려받을 수 있다(2026-10-14 보안 점검 SEC-4). 예전 판의 «팀 선수단» 공유(`kind='team'`)가 남아 있으면 이름·번호·포지션도 들어 있다.

## 무엇을

- `ps_share_get(p_id text)` — id 형식(소문자·숫자 6~16자) 검사 뒤 그 한 건의 `v` 만 돌려준다. SECURITY DEFINER · search_path 고정 · anon/authenticated 실행.
- `ps_share` 테이블 SELECT 를 PUBLIC·anon·authenticated 에서 회수한다. 올리기(INSERT, `Prefer: return=minimal`)는 SELECT 가 필요 없어 그대로다.
- 3.041 앱은 RPC 를 먼저 부르고, **함수가 없을 때(404)만** 옛 GET 으로 돌아간다 — 서버·앱 어느 쪽을 먼저 내도 링크는 열린다.

## 적용 (SQL 편집기, 사람이)

0. 먼저 읽기 전용으로 지금 모양을 본다:
   `select polname, cmd, roles, qual from pg_policies where tablename='ps_share';` ·
   `select column_name, data_type from information_schema.columns where table_name='ps_share';` ·
   `select kind, count(*) from ps_share group by 1;`
1. `20261015_share_get.sql` 전체 실행.
2. `20261015_share_get.verify.sql` — 기대: `share_get_verified`.
3. 아무 공유 링크 하나를 시크릿 창에서 열어 본다(열려야 한다).
4. 시크릿 창 콘솔에서 `fetch('<supabase>/rest/v1/ps_share?select=id',{headers:{apikey:'<anon>'}})` 가 401/403 인지(목록이 더는 안 나와야 한다).

되돌리기: `20261015_share_get.rollback.sql`(SELECT 를 돌려주고 함수를 지운다. 앱은 옛 GET 으로 돌아간다).

## 남은 일(이 파일이 하지 않음)

- 만료(예: 90일)와 작성자 삭제 — 운영 테이블에 `created_at`·작성자 열이 있는지 0번에서 확인한 뒤 따로 만든다.
- 남은 `kind='team'` 공유본 정리 — 0번 결과를 보고 운영자가 판단한다.
- id 길이(지금 8자) 늘리기 — `board.html` 의 id 생성과 함께.
